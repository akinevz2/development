# Git & Commit Guardrails

## Credential handling

- **Never write a person's name or email address into any file**, including this
  one, commit messages, configs, or scripts. Git identity is sensitive PII.
- Git credentials are configured at container start by
  `.devcontainer/update-dots.sh`, which reads `~/.my-credentials` (a file that
  lives outside the repo and is never committed). Do **not** hardcode, echo, or
  replicate those credentials anywhere.
- To see the active identity, read it from git at runtime:
  ```bash
  git config user.name
  git config user.email
  ```
  Never assume or guess an identity. If both are empty/unset, **do not commit** —
  stop and ask the user to provide credentials.

## Commit authorship

- Only create commits under the identity currently configured in git
  (`git config user.name` / `git config user.email`). Do not pass `--author`,
  override `user.name`/`user.email`, or commit as anyone else.
- If the configured identity does not belong to the current user of the
  container, **refuse to commit** and explain that the credentials belong to
  the container owner.
- Never enable credential caching/storage, copy SSH keys, or persist secrets
  to disk on behalf of a user.

## Scope

This devcontainer is configured for a single owner. These guardrails exist so
that if another user (human or agent) ever operates in this container, they
cannot accidentally or intentionally create commits under the owner's identity.
